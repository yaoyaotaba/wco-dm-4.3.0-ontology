WCO Data Model 4.3.0 Ontology Knowledge Base

Built from the official WCO package's LIB (element library) and OIS (Overall Information Structure) workbooks. It provides an OWL 2 DL ontology, SKOS code lists, SHACL shapes and an interactive explorer.

Download Turtle Download RDF/XML

Sources and build method

Source files come from the WCO Data Model 4.3.0 package page. The package exposes a file tree through GET /datamodel/infopage/4.3.0; files are served under /webpage/4.3.0/….

  • LIB: 270 class definitions, 835 data elements, formats, core data types, code-list catalogue and UN/CEFACT superclass alignment.
  • OIS: 1,993 class occurrences and 7,810 attribute occurrences, used to recover containment roles and context.
  • Union of both: LIB-only 42A Declaration, 58C AIP, 74B LPCO and 599 Net weight are added. The three root documents are attached under OIS and explicitly flagged as inferred placement.

Full source list, checksums and download status: download-manifest.csv.

Standards and serialisations

  • OWL 2 DL: 274 classes (including the OIS root), 273 object properties and 836 datatype properties; every class is a subclass of wco:DataModelComponent.
  • RDF 1.1 Turtle is the canonical serialisation; RDF/XML and JSON-LD 1.1 are also provided. All three contain 26,663 triples.
  • SKOS: 135 skos:ConceptScheme resources and 69 code values as skos:Concept.
  • SHACL: NodeShape/PropertyShape graph with 18,459 triples; class-level datatype, length, pattern, target-class and sh:maxCount 1 constraints.
  • PROV-O / DCAT 3 / VoID: provenance, build activity, checksums and dataset catalogue.

Example SPARQL

PREFIX wco: <https://w3id.org/wco-dm/4.3.0#>
PREFIX rdfs: <http://www.w3.org/2000/01/rdf-schema#>

# 1. Data properties of a class
SELECT ?p ?label ?range WHERE {
  ?p a owl:DatatypeProperty ;
     rdfs:domain ?d ;
     rdfs:range ?range ;
     rdfs:label ?label .
  FILTER(?d = wco:C_42A)
}

# 2. Parents containing GoodsShipment
SELECT ?parent WHERE {
  ?parent wco:hasGoodsShipment wco:C_67A .
}

Because domains are union class expressions, a simple triple query does not enumerate all domain members; use the wco:usedByClass annotation as well.

Package profiles (Profile Layer)

The core ontology answers “what a WCO DM class/property is”; the profile layer answers “how a given package uses it”. Four packages are modelled as prof:PackageProfile; package classes are OWL subclasses of core classes (e.g. prof:P_BIP_DEC_C_42A rdfs:subClassOf wco:C_42A); package data elements are prof:ProfileProperty individuals.

Profile graph: 25,407 triples, 387 profile classes, 1,541 data elements, 1,077 associations, 37 flags; profile SHACL: 14,248 triples. The conforming sample passes; the duplicate dp_D014 sample fails under Max=1.

Files: profiles.ttl · profiles-shapes.ttl · profile-layer.md

Modelling conventions and limitations

  • LIB global attributes are modelled as global properties: data elements merge by Attr. ID, roles merge by role name, and domains use owl:unionOf for multiple using classes.
  • Classes are not related by rdfs:subClassOf taxonomy; the OIS hierarchy is containment/composition, so it is represented with object properties.
  • Cardinalities come from the four package sheets: all 8,212 data-element rows are Min=0, Max=1, written as wco:minOccurs / wco:maxOccurs and SHACL sh:maxCount 1. Object-role maxima vary by package and are not asserted globally.
  • Code lists only include values explicitly published in the LIB; no meanings are invented. External UN/EDIFACT and ISO lists keep only their source note.
  • WCO XML dates use CCTS DateTimeString + formatCode; for semantic querying they are normalised to xsd:dateTime, while the original wco:format is retained.
